# Add Skills Sync Proposal

## Why

### Initial Requirements and Drivers

The `riftonix.github.io` site publishes 66 agent skills under `static/.well-known/skills/`, described by `index.json`. Every published skill is a copy of a third-party skill taken from a public GitHub repository or generated by the OpenSpec CLI. The repository owner wants these copies to follow their upstream sources automatically: a nightly job should detect upstream updates with Updatecli and propose them as pull requests, without manual secret provisioning.

### Current Solution

- Skills are copied and refreshed manually.
- Some `index.json` entries record provenance in `metadata.source` and `metadata.revision`, but no entry records the directory inside the upstream repository or the tracked branch, and 32 entries record no provenance at all.
- Entry metadata is inconsistent: gamedev entries carry a non-standard top-level `version` that duplicates the commit SHA, one entry carries a `metadata.version` that does not exist in the upstream frontmatter, and k8s entries omit `tools` and `category` keys present in their upstream frontmatter.
- OpenSpec skills are produced by running the OpenSpec CLI, and their text depends on CLI options, so they cannot be compared with a git tree directly.
- Daggerverse has no Updatecli module and no scenario for synchronizing files from upstream sources.

### Business Problems

- Published skills silently drift from upstream: for example, the k8s skills are pinned to an upstream commit from January 2026 while upstream has released v2.0.0 and removed `k8s-browser`.
- Manual refreshes are error-prone: files can be missed, renamed skills can lose their local name, and index metadata can diverge from the published files.
- Without recorded upstream paths and refs, nobody can reproduce or verify where a published skill came from.

## Stakeholders

- Repository owner of `riftonix.github.io` and `daggerverse`: maintains the published skills and reviews synchronization pull requests.
- Consumers of the published skills index: agents and tools that read `/.well-known/skills/index.json`.

## What Changes

### Goals

- Detect upstream updates for every published skill from git repositories and npm packages.
- Propose each detected update as a reviewable pull request that contains the exact upstream text and a consistent index entry.
- Run unattended on a schedule using the built-in CI token of the site repository.
- Keep the Updatecli integration reusable for other Daggerverse consumers.

### Scope

- New reusable `modules/updatecli` Dagger module that runs Updatecli manifests.
- New `scenarios/skills-sync` Dagger scenario that validates a skills index, renders Updatecli pipelines for its upstream sources, and synchronizes skill directories and index entries locally or through GitHub pull requests.
- A unified, string-valued upstream provenance contract inside each index entry `metadata`: `sourceType`, `source`, `path`, `ref`, and `revision`. These keys are a Riftonix convention; neither the Agent Skills specification nor the Agent Skills Discovery RFC defines them.
- Support for `git` sources and `npm` sources, including OpenSpec skills generated by the OpenSpec CLI.
- Repository documentation for the new module and scenario.
- Dependent work in other repositories tracked as external tasks: a runtime image in `container-images`, index migration and workflows in `riftonix.github.io`, and optional Actions permission codification in `iac/github`.

### Non-Goals

- Migrating the published index to Agent Skills Discovery RFC v0.2.0 (`/.well-known/agent-skills/`, `$schema`, `digest`).
- Automatic merging of synchronization pull requests.
- Local modifications of upstream skill text other than the frontmatter `name`.
- Inferring versions that the upstream source does not declare.
- CI providers other than GitHub for pull request creation.

## Capabilities

### New Capabilities

- `updatecli-module`: Reusable Dagger module contract for running Updatecli manifests with configurable runtime image, secrets, and working tree.
- `skills-sync-scenario`: Scenario contract for skills index provenance metadata, upstream update detection, skill synchronization rules, and pull request proposal.

### Modified Capabilities

None.

## Impact

### Users and Business Processes

- The site owner reviews and merges nightly synchronization pull requests instead of refreshing skills manually.
- Published skills change only through those pull requests; the first run updates the k8s skills, removes `k8s-browser`, replaces locally edited `python-code-style` text with upstream text, and normalizes metadata.

### Systems and Components

- `daggerverse`: new `modules/updatecli` and `scenarios/skills-sync` components with Dagger test modules, README files, and docs pages.
- `container-images`: new runtime image with Updatecli, git, Python, and Node.js.
- `riftonix.github.io`: migrated `index.json`, a new scheduled workflow, and a manual dispatch trigger on the existing CI workflow.
- `iac/github`: optional codification of the repository Actions workflow permissions.

### Data and Integrations

- `index.json` entries gain the provenance keys and lose non-standard fields that are not taken from upstream frontmatter.
- The scenario reads public GitHub repositories over git and the public npm registry, and executes the OpenSpec CLI from npm during synchronization.
- Pull requests are created through the GitHub API with the site repository built-in `GITHUB_TOKEN`.

### Operational Impact

- A nightly scheduled job runs in the site repository and can open one pull request per upstream source group.
- Pull request CI for synchronization branches is started explicitly by the scheduled job, because GitHub does not start `pull_request` workflows for pull requests created by the built-in token.
- New released versions of the module, scenario, and runtime image require Renovate-tracked tags.
